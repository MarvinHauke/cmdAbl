# `link`: named controls with rules for numeric values

**Status:** Draft, idea only (2026-10-22). No builder tasks yet. Trigger: `vol -6 #drums` loses the
balance of a group when a fader runs into a limit; the user wants a layer that defines how grouped
numeric values behave.

**Parent:** [0004](0004-command-platform.md)
**Related:**
- [0008](0008-tags-and-aliases.md): tags are the members; aliases stay text;
- [0012](0012-vol-and-dca.md): `vol` has the first rules, and `dca` is close to a link;
- [0009](0009-ideas-from-clyphx.md): named values and value changes.

## Context

- **`vol` changes faders relative to where they are.** A fader stops at +6 dB and at -inf. What
  happens to the rest of a step is a rule.
- **`vol` has two rules today** (0012, 2026-10-22):
  - `stop` (default): the step shrinks so no member crosses a limit;
  - `--clip`: each member moves by the full step, and the ones at a limit clamp.
- **The pattern repeats** for every command that sets a number: volume, pan, sends, device
  parameters. On/off states (mute, solo, arm) have no limits and need no link (user, 2026-10-22).

## The idea

A **link** binds a parameter of a tag's members to a **named control** with a rule:

```
link @drums = vol #drums --at-limit keep   # creates @drums, value 0 dB (an offset)
vol -3 @drums                              # moves the control; members follow by the rule
link -l                                    # controls, members, offsets, overflows
link --rm @drums
```

A link is a generalised DCA (0012): one fader that offsets several faders.

### Rules at a limit

| Rule | What happens | Balance | Needs memory |
|---|---|---|---|
| `keep` | Each member remembers its intended level (Snare +9 while the fader shows +6). Steps work on the intended level, so `-6` brings Snare back to +3. | kept | yes |
| `stop` | The group stops when its first member reaches a limit, like one hardware fader. | kept, range shrinks | no |
| `clip` | A member at a limit clamps and loses what went past it. Going back, it moves from the clamped value; members away from the limit keep their spacing. Kick -10, Snare +3: `+6` → -4 / +6; `-6` → -10 / 0. | lost for clamped members | no |

**Why `keep` needs memory:**
- A fader can't go past +6 dB, so "Snare should be at +9" exists nowhere in Live. cmdAbl must store
  it, per member, in the Set (`Track.set_data`, like tags).
- The link list itself goes in `Song.set_data` (the same spike as 0013).

### Limits are controls too

A link's limits can be named controls themselves, so links chain:

```
link @drums = vol #drums --max @ceiling
```

- A control can be driven by a command or by another link.
- This makes layered setups possible (a master ceiling for several groups).
- See the risks below for cycles.

### Code shape

- One pure function, `applyRelative(levels, delta, rule, memory?)`, returns the new levels, the
  applied step and the members that hit a limit. `vol` uses it today without memory (`stop`,
  `clip`).
- When `link` arrives, the function moves to the link layer. Every numeric command asks the link
  layer which rule applies.

## Risks: where it loses atomic or functional behaviour

| Risk | Fix |
|---|---|
| An alias is stateless text, while a link has a value and memory. | Keep them apart: an alias is text; `@name` is a stateful control. |
| Cmd+Z, hand moves and automation change faders but not the link's memory, so the two drift. | Self-healing: store only the offset and each member's overflow. On every run, a fader that isn't where cmdAbl expects it counts as moved by hand, and its memory resets. |
| Is the control's value a level or an offset? | Always an offset: 0 dB means the members as they are. `--set` on `@drums` sets the offset. |
| A track gets or loses the tag. | It joins at offset 0. When it leaves, its fader stays where it is. |
| Two links on one parameter (Snare in `@drums` and `@snares`). | Offsets add, as with DCAs. One rule per parameter per track; otherwise `link` refuses with a clear message. |
| Chained links form a cycle or apply a curve twice. | Links form a tree: `link` refuses a cycle, and a curve belongs to one link only. |
| A command's result depends on hidden state. | `link -l` shows offsets and overflows; every write logs before → after. |

## Open questions

- Should `keep` with memory come before `link`, inside `vol`? Not now (user, 2026-10-22).
- How does `link` relate to `dca`? Does `dca` become a link whose overflow goes into the Utility
  gain? Decided in the `dca` plan.
- How are controls named: `@name`, or `$name` as in 0009's named values?
- Where do the controls' current values live, and do they survive Save As? This needs the 0013
  spike.

## Phased rollout

1. Done in `vol`: `stop` and `clip` as a pure function, with no memory.
2. Spike: `Song.set_data` and `Track.set_data` for link state (shared with 0013).
3. `link` module: named controls, `stop` and `clip`, `link -l`.
4. `keep` with self-healing memory.
5. Limits as controls; chains; the cycle check.
6. A second numeric command (pan or send) uses the same layer.

# `jump`: move the playhead, and jump to stamps

**Status:** In work for 0.1.7 (2026-11-12). From the stamps (0013): the user wants to jump to stamped
points, and moving the playhead is a transport action like the loop ([0026](0026-loop.md)), so it gets its
own module (user, 2026-11-12; "playposition" too long). Reading stamps back goes into 0.1.7 with it.

**Depends on:** Remote Script 0.1.15 (`transport`), [0013](0013-set-note.md) stamps, 0018 page runs.

## Bridge (decided, architect 2026-11-12)

- Op `jump {time}` (beats, >= 0), a write op (token): sets `song.current_song_time`, returns
  `{time}`. Playback keeps running. Live's refusal comes back as `failed` with its reason.
- **No strict read-back:** the playhead moves on while playing, and Live may apply the write on the next
  tick (as it does for `loop`). The op does not fail on a mismatch; it returns what it read and logs a
  debug line. Live test first: does a write read back in the same call?
- `transport` adds `sigNum` and `sigDen`. A script without them reports 0 (unknown); the module then
  refuses bar.beat forms with a clear message instead of guessing 4/4.
- Limit: positions use the **current** time signature, so `12.3.1` is off in Sets with signature changes
  (as in 0026).
- TS: `bridgeOps.jump(bridge, time)` → `{ok: true, time} | {ok: false, code: 1|5, text}`; `SetPort.jump`.
- Platform: `api.pickRows(title, rows, { cursor? })` → index or null — a single-select list of plain rows (`disabled` rows shown, not choosable, skipped by the cursor); first user `note stamp list`.

## Commands (user, 2026-11-12: Q17–Q21)

| Line | What it does |
|---|---|
| `jump 12.3.1` / `jump 12` | to that position / bar |
| `jump +4` / `jump -4` | bars forward / back from the playhead |
| `jump start` / `jump end` | to the beginning / to Live's song length (kept; Live counts the loop end in it, to improve later) |
| `note stamp list` | pick list of the stamps; **the cursor starts on the next stamp after the playhead**; Enter jumps there; stamps without a position are shown, not pickable |
| `note stamp next` / `prev` | the next / previous stamp from the playhead, by position |

- **At the ends:** setting **`note.stampWrap`** (bool, default off): off = exit 3 "no stamp after bar N";
  on = wraps to the first / last stamp.
- **On the note page in view:** Enter or a click on an `@12.3.1` heading runs `jump 12.3.1` (page run; the
  allowlist gains `jump`); ↑/↓ move between stamp headings. The page stays open.
- **Behind the end of the song** (user finding, 2026-11-12): Live refuses a jump past `songLength` with a raw
  RuntimeError. `jump` and the stamp commands check first and answer exit 1 (Set state, not a bad input, so not 2;
  `loop` has no pre-check and only maps Live's text): "244.3.4 is behind the end of the song (it ends at 58.3.1)"; no write. Live's two known
  "behind the Songlength" refusal texts (jump and loop) are mapped to "that is behind the end of the song", Live's
  text goes to the log only. `note stamp next/prev` leave unreachable stamps out, so `note.stampWrap` still wraps
  and the end gives exit 3 "no stamp after bar N (2 behind the end of the song)"; `list` shows them disabled
  with the detail "behind the end of the song" (date-only: "no song position").
- Stamps without a position (made while stopped) are skipped by next/prev. Session stamps (linked to a
  scene) come later with Session View support (0013 item 6).
- The note module parses its own file (`### @bar.beat.sixteenth · date`); both modules use `SetPort.jump`.
- Not the same as the pick list's **follow mode** (0007, not built: the row under the cursor is selected
  in Live while browsing). Page runs now make follow mode possible; it stays a later item.
- **Jumps behind the song end stay refused** (user, 2026-11-12). Live's song length is the largest of the
  last clip's end, the loop's end and the playhead + 8 bars, and Live refuses a song time beyond it (a loop
  end beyond it too). Reaching e.g. bar 110 would need 8-bar steps over several ticks: a hack, not done.
  The message "… is behind the end of the song" stays. Revisit if Live or the SDK offers a real way.
- Later with substitution (0017): `jump $(note stamp prev)`.
- **Step size (user, 2026-11-12; 0.1.8+):** setting `jump.step`, default Live's global launch
  quantization, overridable in `jump config`; `+N`/`-N` count steps; explicit units `+2b` (bars), `+3q`
  (quarters).

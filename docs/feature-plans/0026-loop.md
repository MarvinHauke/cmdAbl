# `loop`: the arrangement loop as its own module

**Status:** In work for 0.1.7 (2026-11-11). From the stamps (0013): the loop while writing belongs to
Live's transport, not to the note (user, 2026-11-11). Replaces `note stamp loop`/`unloop` (never released).

**Depends on:** Remote Script 0.1.15 (`transport`, `loop_set`), `api.set.transport()/setLoop()` (0013).

## Commands

| Line | What it does |
|---|---|
| `loop` | shows the current loop (on/off, start bar, length in bars) |
| `loop here [bars]` | loops from the current bar, `bars` long (default `loop.bars`, 4), switches it on, and remembers the loop before |
| `loop on` / `loop off` | switches the loop on or off |
| `loop back` | puts back the loop from before the last `loop here`, only if it is still the one `loop here` set; else leaves it alone |

- `loop` typed alone runs the bare fallback child `show` (0005 "the `git stash` rule").
- Bars use the Set's current time signature (`barLen` from `transport`; a limit with signature changes).
- Without the Remote Script: exit 5. Nothing to restore: exit 0 with a log line.
- Setting: `loop.bars` (int 1–64, 4). The loop write leaves no undo step (Live 13 spike); the Set counts as changed.

## The note uses it (0013)

- The note page runs `loop here` on `s` and `loop back` when the stamp ends (Esc, Done, Discard, Cmd+S):
  page runs with the allowlist `["loop here", "loop back"]`. The note keeps no loop logic of its own.
- Whether the page loops comes from the note: its `heading` route answers `{heading, hint?, loop}`,
  `loop` true only with `note.stampLoop` on and Arrangement playback (not Session, not stopped).
- **Safety net:** `livePage(…, { run, onClose })`: core runs the `onClose` line headless after the page
  closes, here `loop back` (it only restores a loop that `loop here` set and nobody moved). Additive to
  the page-run contract (0018), architect 2026-11-11.
  It runs only if the page made at least one page run (reviewer, 2026-11-11), so reading the note never
  undoes a loop set by hand. Without the server (data page, `LIVE = null`) a stamp does not loop (accepted:
  only when the port is taken).
- `note stamp` alone already loops (the page runs `loop here`, and `loop back` when the stamp ends or the
  page closes), also from a chain or a MIDI binding; no extra `loop` parts are needed (reviewer,
  2026-11-12; an earlier `loop here; note stamp; loop back` example was wrong).

## Later
